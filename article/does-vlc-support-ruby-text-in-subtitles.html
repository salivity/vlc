Does VLC Support Ruby Text in Subtitles?

VLC Media Player does not natively support the proper rendering of Ruby text (furigana) found in standard subtitle formats like WebVTT or TTML. When playing media with Ruby annotations, VLC typically flattens the text, displaying the phonetic guides directly inline next to the base characters rather than positioning them above. While VLC can display simulated Ruby text created through complex, manually positioned Advanced SubStation Alpha (ASS) files, true markup-based Ruby rendering remains unsupported.

How VLC Handles Ruby Text Across Formats

  • WebVTT (.vtt): Modern WebVTT supports the HTML5-style <ruby> and <rt> tags designed for East Asian typography. VLC parses basic WebVTT styling (such as bold, italic, and underline), but its text renderer ignores Ruby markup. Consequently, VLC renders both the base character and the annotation consecutively on the same line, resulting in cluttered and hard-to-read text.
  • Timed Text Markup Language (TTML): TTML includes native specifications for Ruby positioning (tts:ruby). VLC's internal TTML decoder provides only minimal support for complex layout properties, causing Ruby tags to be stripped or rendered inline.
  • SubStation Alpha / Advanced SubStation Alpha (.ssa / .ass): The ASS format does not feature an automated "ruby" tag. However, creators frequently achieve the Ruby effect by using two separate, synchronized text events—one positioned directly above the other—or by using \pos and \fscx override tags. Because VLC utilizes the libass library for ASS rendering, these manually constructed Ruby subtitles display correctly.
  • SubRip (.srt): The standard SRT format does not support Ruby tags. Any attempt to include <ruby> markup in an SRT file will either be stripped by VLC or displayed as raw, unparsed code on screen.

Why the Limitation Exists

VLC utilizes its own internal text-rendering engine (primarily FreeType) alongside custom decoders for plain text formats. Unlike web browsers or full-fledged typography engines, VLC's text layout engine is linear. It lacks the multi-line layout intelligence required to calculate character widths, align phonetic annotations centered above base glyphs, and prevent annotations from overlapping adjacent text.

Practical Workarounds

If you need to view media with proper Ruby text:

  1. Convert to Styled ASS Subtitles: Tools like Aegisub allow you to generate subtitles where furigana is manually placed over kanji using absolute positioning or template scripts. VLC will render these accurately.
  2. Use a Web Browser: If your media uses WebVTT subtitles with <ruby> tags, modern browsers (such as Chrome, Firefox, or Edge) have full HTML5 Ruby support. Playing the video inside a browser via a simple HTML <video> tag will render the furigana above the base text correctly.
  3. Alternative Media Players: Certain specialized media players and tools built directly on modern web frameworks or advanced libass scripting handle complex Asian typography better than VLC's default interface.
